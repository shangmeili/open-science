# Preference proposal contract

A proposal is a local draft supported by at least two independent interaction
references. It must state a narrow scope, the proposed work-style rule,
supporting observations, known counterexamples, and a review condition.

Allowed scopes include output language, terminology, file format, table layout,
or a repeated request for a particular audit field. Scientific methods,
comparators, evidence choices, assumptions, parameter values, conclusions,
approval choices, provider selection, data-routing permission, and release
permission are never preferences.

The proposal remains inactive under `learning/proposals/`. Only an app-owned
Human action can copy an edited, accepted rule into `learning/preferences.json`.
